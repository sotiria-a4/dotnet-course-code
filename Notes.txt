What is?
is a tool that we can use again to connect to the database a lot like Dapper but with Entity Framework we don't have to actually write any kind of SQL code or SQL Queries.

We can handle this as "entities".
So we can connect to sql table and trat it like that table was an entity inside of our program and then we have our persistent storage managed by EF and the database kind separately and wee can just write out code in c#.

DbContext is a base class that we can inherit from to build our connections out and wht that basically means is we can connect to the DB context class and get access to what it's already doing by inheriting from it. So what we do when we inherit from a class is we create basically a copy of that class and everything in it and get all of the logic that was already built inside of that class And then we have the ability to add to that or to override parts of that.

The next thing we're gonna do is hook into a method of DB context and override it. So we are gonna replace an existing method with a new override method of something called OnConfiguring - UseSqlServer. Now OnConfiguring is something that's gonna fire whenever we create an instance of EF.
So when we inherit from DB context, we create our class then we create an instance of that class to access the logic inside of it.
The next thing  we're gonna talk about is what happens when we create an instance of a model -  OnModelCreating. So we're gonna have something called on model creating that we 're also gonna override.
This means if we connect to a table inside of this sql server which is how we will be setting this up, then when we create an instance of that connection to the table. This is how we can tell it where to look for that table inside of the database. So on configuring TELLS IT WHERE THE DATABASE IS and then all models creating tell it WHERE THE TABLE IS INSIDE OF THE DATABASE.

So once were in on model creating we can use something called entity to tell it where A DB said lives.

With System.Text.Json (built into .NET) we first have to configure one option, because it is case-sensitive: JsonSerializerOptions with PropertyNamingPolicy = JsonNamingPolicy.CamelCase.


inside the main

 IConfiguration config = new ConfigurationBuilder()
                .AddJsonFile("appsettings.json")
                .Build();

3. read the file e.g Comptuers.json
4.     JsonSerializerOptions options = new JsonSerializerOptions()
            {
                PropertyNamingPolicy = JsonNamingPolicy.CamelCase             };
5. Deserialize :  IEnumerable<Computer>? computers = JsonSerializer.Deserialize<IEnumerable<Computer>>(computersJson, options);

6. print foreach (Computer computer in computers) ...

OR we could that using NewtonSoftJson

1. add the package dotnet add package NewtonSoft.Json
2. read the file :  string computersJson = File.ReadAllText("Computers.json");
3. deserialize:   IEnumerable<Computer>? computers = JsonConvert.DeserializeObject<IEnumerable<Computer>>(computersJson);
we dont need options here because Newtonsoft ignores upper/lower case when deserializing. On Serialize the default is PascalCase.
